## TL;DR

- OpenRouter の `:free` サフィックス付きモデルは 2026 年時点で **15 本以上**が常時利用可能
- 日本語応答品質・レイテンシ・コンテキスト長の 3 軸で比較すると **用途別の最適解**がはっきり分かれる
- 自動化パイプラインなら `qwen/qwen3-235b-a22b:free` か `google/gemini-2.0-flash-exp:free` が現状トップ候補
- 英語コーディング補助なら `deepseek/deepseek-r1:free` が圧倒的コスパ

---

## 背景: なぜ OpenRouter `:free` モデルを真剣に評価するのか

LLM を業務自動化に組み込む際、コストは無視できない変数です。OpenAI GPT-4o や Anthropic Claude 3.5 Sonnet をすべてのタスクに使えば月額が青天井になる一方、品質を妥協すると出力が使い物にならない。

OpenRouter は単一 API エンドポイントで 200 以上のモデルへのアクセスを提供するルーターサービスです ([openrouter.ai](https://openrouter.ai))。その中に `:free` サフィックスが付いたモデル群があり、これらは **レート制限はあるものの料金ゼロ** で呼び出せます。

「無料モデルは品質が低い」という先入観は 2025 年末以降、急速に崩れています。Qwen3・Gemma 3・DeepSeek R1 の OSS 公開によって、無料枠で使えるモデルの性能が商用モデルの 1 世代前に追いつきつつあるからです。

本記事では、2026 年 5 月時点での代表的な `:free` モデルを **3 つの軸**で体系的に整理します。

---

## 評価軸の定義

### 軸 1: レイテンシ (TTFT + スループット)

- **TTFT (Time To First Token)**: プロンプト送信からストリーミング開始まで
- **スループット**: tokens/sec (出力速度)
- 目安: TTFT < 2s ならインタラクティブ用途可 / > 5s ならバッチ限定

### 軸 2: 日本語応答品質

- 指示追従 (instruction following) の正確さ
- 出力の自然さ・文法的正しさ
- コードと日本語混在タスクへの対応

### 軸 3: コンテキスト長

- 長文ドキュメント要約・長い会話履歴の保持に直結
- 32k / 128k / 1M の区分で実用度が大きく変わる

## 詳細評価

### 🥇 Qwen3-235B-A22B (MoE)

**`qwen/qwen3-235b-a22b:free`**

Alibaba が 2025 年 4 月に公開した Qwen3 シリーズの最大モデル。235B 総パラメータのうちアクティブは 22B という MoE 構成により、推論コストを抑えながら高品質な出力を実現しています。

**特徴**
- **Thinking モード対応**: `enable_thinking: true` を渡すことで内部 Chain-of-Thought が走り、数学・ロジック問題の正答率が大幅向上
- **日本語品質**: Qwen2.5 から大幅改善。ビジネス文書・技術翻訳レベルの日本語を自然に生成
- **コンテキスト 128k**: 長文 PDF 要約・長い会話ログの処理も実用域

**ユースケース**
- 複雑な指示追従が必要な自動化タスク
- 日本語・英語・中国語の多言語混在ドキュメント処理

**注意点**
- MoE モデルの common issue として、プロバイダー側の GPU 空き状況によって TTFT がばらつく
- Thinking モードは出力トークンが増えるため、スループット换算の「実用速度」は下がる

---

### 🥈 Gemini 2.0 Flash Experimental

**`google/gemini-2.0-flash-exp:free`**

Google の Gemini 2.0 シリーズの中で最もレイテンシが低いモデル。1M コンテキストウィンドウが `:free` で使える点は他の無料モデルにはない強みです。

**特徴**
- **TTFT が最速クラス**: Flash 系列の設計思想通り、インタラクティブ応答に最適化
- **1M コンテキスト**: 書籍 1 冊相当のテキストを一括処理できる
- **マルチモーダル**: 画像入力対応 (テキスト+画像の複合タスクも無料枠で試験可)

**ユースケース**
- リアルタイムチャット補助・ストリーミング UI への組み込み
- 大量の長文ドキュメントをまとめてコンテキストに詰め込む RAG 前処理

**注意点**
- `experimental` フラグ付きのため、API 仕様が予告なく変更される可能性あり
- 無料枠では 1 分あたりのリクエスト数制限が厳しい (RPM 制限はダッシュボードで要確認)

---

### 🥉 DeepSeek-R1

**`deepseek/deepseek-r1:free`**

DeepSeek が 2025 年 1 月に MIT ライセンスで公開した推論特化モデル。671B (MoE, アクティブ約 37B) の規模ながら、数学・コーディング・論理推論ベンチマークで GPT-o1 に匹敵する成績を示したことで注目を集めました。

**特徴**
- **MIT ライセンス**: 商用利用可 / 派生モデル可の最も自由なライセンス
- **推論特化**: ベンチマーク AIME 2024 で 79.8%、Codeforces で rating 2029 (公式発表)
- **Thinking tokens**: `<think>...</think>` タグで内部推論過程が可視化される

**ユースケース**
- アルゴリズム問題・競技プログラミングの補助
- 複雑なバグ解析・デバッグの壁打ち

**注意点**
- 日本語の instruction following は Qwen3 より弱い傾向
- Thinking tokens が非常に長くなることがあり、タイムアウトに注意

---

### Llama 4 Maverick / Scout

**`meta-llama/llama-4-maverick:free`** / **`meta-llama/llama-4-scout:free`**

Meta が 2025 年 4 月にリリースした Llama 4 シリーズ。Maverick (400B MoE) と Scout (109B MoE, **10M コンテキスト**) の 2 本が無料枠で提供されています。

**Scout の特徴**
- **コンテキスト 10M**: 業界最長クラス。コードベース全体を一度に渡す用途を想定
- Early Fusion マルチモーダルアーキテクチャ採用
- Llama 4 公式ページ: [ai.meta.com/blog/llama-4-multimodal-intelligence](https://ai.meta.com/blog/llama-4-multimodal-intelligence/)

**Maverick の特徴**
- GPT-4o と同等以上とされる汎用品質 (Meta 公式ブログ比較)
- 画像・テキスト混在入力に対応

**注意点**
- Scout の 10M コンテキストは 2026 年 5 月時点では OpenRouter 経由では最大 128k で運用されているケースが多い (プロバイダー制約)
- Llama 4 は **Llama 4 Community License** (Meta 独自) であり、大規模展開には条件あり

## 実装: OpenRouter `:free` モデルの切り替えパターン

OpenRouter は OpenAI 互換 API を提供しているため、`OPENAI_BASE_URL` と `OPENAI_API_KEY` を差し替えるだけで既存コードが動作します。

### Python (openai SDK)

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://openrouter.ai/api/v1",
    api_key="<YOUR_OPENROUTER_KEY>",
)

# モデルを変数化して切り替えを容易にする
FREE_MODELS = [
    "qwen/qwen3-235b-a22b:free",
    "google/gemini-2.0-flash-exp:free",
    "deepseek/deepseek-r1:free",
]

def chat(prompt: str, model: str = FREE_MODELS[0]) -> str:
    response = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": prompt}],
        extra_headers={
            "HTTP-Referer": "https://your-app.example.com",  # OpenRouter 推奨
            "X-Title": "My App",
        },
    )
    return response.choices[0].message.content
```

### Thinking モード (Qwen3 のみ)

```python
response = client.chat.completions.create(
    model="qwen/qwen3-235b-a22b:free",
    messages=[{"role": "user", "content": "1+1=2 を証明してください"}],
    extra_body={"thinking": {"type": "enabled", "budget_tokens": 2000}},
)

# thinking コンテンツは choices[0].message.reasoning_content で取得
reasoning = response.choices[0].message.model_extra.get("reasoning_content", "")
answer = response.choices[0].message.content
```

### フォールバック付きローテーション

`:free` モデルは混雑時に 429 (Too Many Requests) を返すことがあります。シンプルなフォールバック実装例:

```python
import time
from openai import RateLimitError

def chat_with_fallback(prompt: str) -> str:
    for model in FREE_MODELS:
        try:
            return chat(prompt, model=model)
        except RateLimitError:
            print(f"Rate limited on {model}, trying next...")
            time.sleep(1)
    raise RuntimeError("All free models rate limited")
```

### TypeScript / Node.js

```typescript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://openrouter.ai/api/v1",
  apiKey: process.env.OPENROUTER_API_KEY,
  defaultHeaders: {
    "HTTP-Referer": "https://your-app.example.com",
  },
});

const FREE_MODELS = [
  "qwen/qwen3-235b-a22b:free",
  "google/gemini-2.0-flash-exp:free",
  "deepseek/deepseek-r1:free",
] as const;

async function chat(
  prompt: string,
  model: (typeof FREE_MODELS)[number] = FREE_MODELS[0]
): Promise<string> {
  const res = await client.chat.completions.create({
    model,
    messages: [{ role: "user", content: prompt }],
  });
  return res.choices[0].message.content ?? "";
}
```

## レート制限の実情と対策

OpenRouter `:free` モデルのレート制限は公式ドキュメント ([openrouter.ai/docs/limits](https://openrouter.ai/docs/limits)) によると:

- **RPM (Requests Per Minute)**: モデル・プロバイダーによって異なる。一般的に 10〜60 RPM
- **TPD (Tokens Per Day)**: 無料アカウントは全モデル合計で上限あり (ダッシュボードで確認)
- **有料クレジット追加**: $5 以上チャージするとレート制限が緩和される

### 現実的な使い分け戦略

```
高頻度・軽量タスク (分類・キーワード抽出)
  → qwen/qwen3-8b:free / mistral-7b-instruct:free

中頻度・品質重視 (日本語文書生成・コードレビュー)
  → qwen/qwen3-235b-a22b:free / deepseek/deepseek-v3-0324:free

低頻度・高品質推論 (数学問題・複雑ロジック)
  → deepseek/deepseek-r1:free

長文処理 (1万字以上のドキュメント要約)
  → google/gemini-2.0-flash-exp:free (1M ctx)
  → meta-llama/llama-4-scout:free (10M ctx)
```

## まとめ

2026 年 5 月時点における OpenRouter `:free` モデルの結論:

1. **日本語自動化パイプライン** → `qwen/qwen3-235b-a22b:free` が最有力
2. **リアルタイム応答・長文 RAG** → `google/gemini-2.0-flash-exp:free`
3. **コーディング・推論** → `deepseek/deepseek-r1:free`
4. **高頻度・軽量** → `qwen/qwen3-8b:free`
5. **コンテキスト最大化** → `meta-llama/llama-4-scout:free`

無料枠とは思えない品質のモデルが揃ってきており、`:free` → 商用モデルへのグレードアップは「本当に必要な時だけ」という設計が現実的になっています。レート制限に当たったらフォールバックを実装する、という構成で月間コストをほぼゼロに抑えながら実用的な LLM パイプラインを組めます。
