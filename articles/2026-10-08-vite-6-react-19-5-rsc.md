## TL;DR

- Vite 6 は **Environment API** を導入し、RSC / SSR / クライアントを同一設定で並列ビルドできるようになった
- React 19 の **Server Components** との統合がより自然な形で書けるようになった
- `resolve.conditions` の整理と CSS Modules の型生成が標準化された
- 既存の Vite 5 プロジェクトはほぼ **破壊的変更なし**で移行できる

---

## 背景：Vite 5 での課題

Vite 5 まで、SSR ビルドとクライアントビルドは内部的に「おまけ扱い」だった。`vite build --ssr` で SSR 用バンドルを出力できたが、設定ファイルの中で `ssr` フラグ分岐が増殖し、プラグインも「クライアント向けなのか SSR 向けなのか」を自分で判断しなければならなかった。

```ts
// Vite 5 以前のプラグイン: 自前で判断が必要
export function myPlugin(): Plugin {
  return {
    name: 'my-plugin',
    transform(code, id) {
      // SSR かどうか判定するために config を参照する必要があった
      if (this.environment?.name === 'ssr') { /* ... */ }
    }
  }
}
```

React Server Components が本格的に普及しはじめると、「クライアント / SSR / RSC」の 3 環境を同時に扱いたいケースが増え、Vite の内部モデルが追いつかなくなってきた。

---

## Vite 6 の核心：Environment API

Vite 6 の最大の変更点は **Environment API** の導入だ。従来の「クライアントとサーバー (SSR) の 2 分割モデル」から、**任意の数の名前付き環境を定義できるモデル**へと刷新された。

### 設定例

```ts
// vite.config.ts (Vite 6)
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
  environments: {
    client: {
      // ブラウザ向けビルド
      build: {
        outDir: 'dist/client',
      },
    },
    ssr: {
      // Node.js SSR 向けビルド
      build: {
        outDir: 'dist/server',
        ssr: true,
      },
    },
    rsc: {
      // React Server Components 向け
      build: {
        outDir: 'dist/rsc',
        ssr: true,
      },
      resolve: {
        conditions: ['react-server'],
      },
    },
  },
})
```

これだけで `vite build` 一発コマンドが **3 環境を並列ビルド**するようになる。

### プラグインから環境を参照する

プラグイン内では `this.environment` で現在どの環境向け処理なのかを識別できる。

```ts
export function reactServerPlugin(): Plugin {
  return {
    name: 'react-server-transform',
    transform(code, id) {
      // RSC 環境のみ "use server" ディレクティブを解析
      if (this.environment?.name === 'rsc') {
        return transformServerActions(code, id)
      }
    },
  }
}
```

## React 19 との統合ポイント

### `react-server` 条件の自動解決

React 19 のパッケージは `package.json` の `exports` フィールドに `react-server` 条件を含む。Vite 6 の `rsc` 環境に `conditions: ['react-server']` を指定すると、`react` インポートが自動的に RSC 用のエントリポイントへ解決される。

```json
// react/package.json (概略)
{
  "exports": {
    ".": {
      "react-server": "./react.react-server.js",
      "default": "./index.js"
    }
  }
}
```

従来はフレームワーク側 (Next.js 等) がカスタムリゾルバで吸収していたが、Vite 6 では **設定 1 行** で対応できる。

### `use client` / `use server` 境界の扱い

Vite 6 + React 19 では、`use client` ディレクティブのあるファイルを RSC 環境からインポートしようとすると、**自動的に「クライアントリファレンス」に変換**するプラグインを公式が用意している。

```ts
// フレームワーク側で1回設定するだけでよい
import { createClientComponentPlugin } from '@vitejs/plugin-react-rsc' // 仮名・各フレームワークが実装

export default defineConfig({
  plugins: [createClientComponentPlugin()],
  // ...
})
```

アプリ開発者は `'use client'` を書くだけでよく、バンドラーの仕組みを意識しなくてすむ。

## CSS Modules の型生成が標準化

Vite 6 では **`css.modules.generateScopedName`** の型定義出力が正式にサポートされた。以前は `typed-css-modules` などの外部ツールが必要だったが、Vite CLI のみで完結するようになった。

### 設定

```ts
export default defineConfig({
  css: {
    modules: {
      // ビルド時に .d.ts を自動生成
      generateScopedName: '[name]__[local]__[hash:5]',
    },
  },
})
```

### 出力される型ファイル

```ts
// Button.module.css.d.ts (自動生成)
declare const styles: {
  readonly container: string
  readonly primary: string
  readonly disabled: string
}
export default styles
```

これで CSS Modules を TypeScript で使うときの `as unknown as CSSModule` キャストや手動 `.d.ts` 管理から解放される。

## 破壊的変更と移行チェックリスト

Vite 5 から Vite 6 への移行は比較的穏やかだ。主な破壊的変更を列挙する。

| 項目 | 変更前 (Vite 5) | 変更後 (Vite 6) |
|---|---|---|
| `ssr.target` のデフォルト | `node` | `node` (変更なし) |
| `resolve.conditions` の順序 | フレームワーク依存で曖昧 | 優先度明示必須 |
| `import.meta.env.SSR` | boolean | 環境名に応じた boolean |
| `vite.ssrLoadModule()` | メイン API | 非推奨 → `environment.fetchModule()` へ |
| `?raw` クエリ | 文字列を返す | 変更なし (後方互換) |

### 実際の移行手順 (5ステップ)

```bash
# 1. バージョンを上げる
pnpm add -D vite@6 @vitejs/plugin-react@latest

# 2. 型エラーを確認する
pnpm tsc --noEmit

# 3. ssrLoadModule の呼び出しを探す
grep -r "ssrLoadModule" src/

# 4. resolve.conditions が明示されているか確認
# (暗黙依存は Vite 6 で警告が出る)

# 5. ビルドを流して出力を確認
pnpm vite build
```

`ssrLoadModule` を使っていなければ、多くのプロジェクトは **手順 1 だけで移行完了**する。

## パフォーマンス比較：並列ビルドの効果

Environment API により、複数ターゲットのビルドが逐次ではなく並列に実行されるようになった。Vite 公式ブログのベンチマーク（中規模 SSR アプリ）では以下のような改善が報告されている（公式リリースノートより）。

| 構成 | Vite 5 逐次ビルド | Vite 6 並列ビルド |
|---|---|---|
| client + ssr | ~12 秒 | ~7 秒 (約 42% 短縮) |
| client + ssr + rsc | ~18 秒 | ~8 秒 (約 55% 短縮) |

ターゲット数が増えるほど恩恵が大きく、モノレポで複数アプリを同時ビルドするケースでは特に効果が顕著だ。

## まとめ

Vite 6 のポイントを改めて整理する。

1. **Environment API** により「クライアント / SSR / RSC」の 3 環境並列ビルドが設定 1 ファイルで完結する
2. **React 19 との統合**が自然になり `react-server` 条件の解決が宣言的に書ける
3. **CSS Modules の型生成**が標準化され外部ツール不要になった
4. **破壊的変更は最小限**で、`ssrLoadModule` を使っていなければほぼノーコスト移行

RSC を本番採用するプロジェクトが増えている現在、Vite 6 の Environment API はフレームワーク作者だけでなく **アプリ開発者が直接触れる** 重要な API になりつつある。特に Remix / TanStack Start などの Vite ベースフレームワークを使っているチームは、早めにアーキテクチャを把握しておくと良いだろう。
